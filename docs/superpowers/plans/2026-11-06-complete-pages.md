# 전체 페이지 기능 연결

요청: 메인에 한정하지 않고 기존 사이트의 모든 페이지를 서버와 연결해 팀원이 함께 검증할 수 있는 상태로 만든다. 별도 로컬 브랜치에서 진행하며 main 병합·push·배포는 제외한다.

기존 Express/PostgreSQL/Storage와 화면 디자인을 유지한다. 새로운 인증 시스템이나 프레임워크를 도입하지 않는다.

1. 실패 테스트로 마이페이지의 미연결 수정·삭제·좋아요 취소 및 프로필 반환 누락을 재현한다. HTTP에서 다른 사용자의 수정·삭제를 차단한다.
2. 사진 설명/장소 수정, 삭제 API와 공통 adapter를 구현한다. 삭제는 DB에서 즉시 숨기고 Storage 실패 시 재시도할 수 있게 삭제 상태를 DB에 보존한다. 기존 사용자의 사진을 자동으로 지우지 않는다.
3. 닉네임과 가입 시각을 profiles 테이블에 보존한다. 내 정보 화면은 로그인 세션으로 접근한다. 학교 비밀번호 변경은 학교 사이트로 연결한다. 가짜 본인 확인/비밀번호 변경 경로를 없앤다.
4. 마이페이지 변경 뒤 목록·통계·지도 동기화, 안전한 장소명 렌더링, 재시도/연속 클릭 방지, 전체 사진 더 보기·정렬 경쟁 응답 방지, 업로드 안내 문구·비로그인 흐름을 완성한다.
5. SQLite/embedded PostgreSQL/API/HTML 테스트와 회귀 검증. 테스트는 실제 Supabase와 분리한다. 실제 서비스에는 추가 스키마만 적용하고 읽기 전용 확인, 사용자 사진을 테스트 중 수정/삭제하지 않는다.

검증 범위: 삭제/수정 소유권, 로그인 차단, Storage 실패 후 재시도, 목록/extent/좋아요에서 삭제 사진 제외, 닉네임 재접속 유지, 마이페이지 삭제·취소 UI와 통계 갱신, 전체 사진 정렬·더 보기·실패 재시도. 실제 학교 인증은 자동 테스트하지 않는다.

## 완료 및 확인
- 기능 구현/설정/문서 완료. Node22 전체 테스트56/56 통과, diff whitespace 검사 통과.
- 별도 코드 검토에서 지적된 인기순 페이지 중복을 ID로 제거하고, 실제 순위 변경을 포함한 HTML 회귀 테스트로 확인.
- 실제 Supabase 추가 스키마 적용(기존 사진 수 보존), 임시 사진으로 Storage 업로드/읽기, DB 수정/좋아요/취소/삭제 확인 후 임시 사진과 세션 정리.
- 로컬 서버3012 재시작 및 메인/전체/마이페이지/업로드/로그인 페이지 HTTP200 확인. 실제 브라우저/지도 상호작용은 연결 도구 불가로 미검증.
- 브랜치에 로컬 저장하며 main 병합/push/공개 배포는 하지 않음. 팀원 확인 순서는 docs/team-verification.md.
